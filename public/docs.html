WhatsApp Checker API

Check whether phone numbers are registered on WhatsApp from your own apps. ← Back to the site

Getting started

  1. Create an account or log in. Your API key is shown on your dashboard.
  2. On the dashboard, click Link WhatsApp and scan the QR code with your phone. Everything your API key does uses this WhatsApp account: checks run through it and messages are sent from it.
  3. Send the key with every request, in the X-API-Key header (or Authorization: Bearer <key>).
  4. Call POST /api/v1/check with the numbers you want to check.

Numbers must include the country code. +201001234567, 00201001234567, +20 100 123 4567 and +20-100-123-4567 are all accepted.

Speed: to protect your WhatsApp account, the server checks about one number every 2.5 seconds for each account. A request with 10 numbers takes about 25 seconds, and one with 50 numbers about 2 minutes. Set your HTTP client's timeout to at least 3 minutes.

Limits: up to 50 numbers per request and 30 requests per minute per API key.

Check numbers

POST/api/v1/check

Checks one or more numbers and returns the answer in the same response. Duplicates in the same request are only checked once.

HeaderValue
X-API-KeyYour API key
Content-Typeapplication/json
Body fieldType
numberstring or array of stringsRequired. 1–50 numbers, each with a country code.

Request:

{
    "number": ["+201001234567", "+201000000000"]
}

Response 200:

{
  "total": 2,
  "summary": { "registered": 1, "not_registered": 1, "invalid": 0, "error": 0 },
  "results": [
    { "input": "+201001234567", "number": "+201001234567", "status": "registered",     "whatsapp": true },
    { "input": "+201000000000", "number": "+201000000000", "status": "not_registered", "whatsapp": false }
  ]
}

If you send a single string ({"number": "+201001234567"}), the response is one result object, not a list:

{ "input": "+201001234567", "number": "+201001234567", "status": "registered", "whatsapp": true }

Result fields:

FieldMeaning
inputExactly what you sent
numberThe normalized number, or null if it is invalid
statusregistered · not_registered · invalid (not a real phone number) · error (the check failed for this number; try again later)
whatsapptrue if it has WhatsApp, false if not, null for invalid or error

Examples:

curl -X POST "BASE/api/v1/check" \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"number": ["+201001234567", "+201000000000"]}'
const res = await fetch('BASE/api/v1/check', {
  method: 'POST',
  headers: { 'X-API-Key': 'YOUR_API_KEY', 'Content-Type': 'application/json' },
  body: JSON.stringify({ number: ['+201001234567', '+201000000000'] }),
});
const data = await res.json();
for (const r of data.results) console.log(r.number, r.whatsapp);
import requests

r = requests.post("BASE/api/v1/check",
                  json={"number": ["+201001234567", "+201000000000"]},
                  headers={"X-API-Key": "YOUR_API_KEY"},
                  timeout=180)
for item in r.json()["results"]:
    print(item["number"], item["whatsapp"])
$ch = curl_init("BASE/api/v1/check");
curl_setopt_array($ch, [
  CURLOPT_POST => true,
  CURLOPT_HTTPHEADER => ["X-API-Key: YOUR_API_KEY", "Content-Type: application/json"],
  CURLOPT_POSTFIELDS => json_encode(["number" => ["+201001234567", "+201000000000"]]),
  CURLOPT_RETURNTRANSFER => true,
  CURLOPT_TIMEOUT => 180,
]);
$data = json_decode(curl_exec($ch), true);
foreach ($data["results"] as $r) echo $r["number"], " ", var_export($r["whatsapp"], true), "\n";

Send messages

POST/api/v1/send

Sends a text message to one or more numbers from the WhatsApp account you linked on your dashboard. Recipients see your number as the sender.

Each number is checked first. Numbers that aren't on WhatsApp are skipped and no chat is opened with them. Messages are sent one at a time, about 6–12 seconds apart, so a request to 20 numbers takes 2–4 minutes. Set your HTTP client's timeout to at least 5 minutes.

Limits: up to 20 numbers per request, 200 messages per day per account (the count resets at midnight UTC), and 4,096 characters per message. Messaging many people who don't have your number saved can get your WhatsApp account banned.

Body fieldType
numberstring or array of stringsRequired. 1–20 numbers, each with a country code.
messagestringRequired. The text to send.

Request:

{
    "number": ["+201001234567", "+201000000000"],
    "message": "Hello from WhatsApp Checker!"
}

Response 200:

{
  "total": 2,
  "summary": { "sent": 1, "not_registered": 1, "invalid": 0, "duplicate": 0, "daily_limit_reached": 0, "error": 0 },
  "results": [
    { "input": "+201001234567", "number": "+201001234567", "status": "sent", "message_id": "true_201001234567@c.us_3EB0..." },
    { "input": "+201000000000", "number": "+201000000000", "status": "not_registered", "message_id": null }
  ]
}

A single string in number returns one result object, not a list. Possible status values: sent · not_registered · invalid · duplicate (the same number appeared earlier in the request) · daily_limit_reached · error.

curl -X POST "BASE/api/v1/send"   -H "X-API-Key: YOUR_API_KEY"   -H "Content-Type: application/json"   -d '{"number": "+201001234567", "message": "Hello!"}'

Errors

Errors return a non-2xx status and this body:

{ "error": { "code": "unauthorized", "message": "Missing or invalid API key. Send it in the X-API-Key header." } }
HTTPcodeWhat to do
400missing_numberSend number as a string or a non-empty array
400too_many_numbersSplit the list into requests of 50 or fewer
400invalid_jsonFix the JSON body
400missing_message, message_too_long/send only: send a non-empty message of up to 4,096 characters
401unauthorizedSend a valid API key (copy it from your dashboard)
429rate_limitedWait a minute and retry
429daily_limit_reached/send only: the 200 messages per day are used up; try again tomorrow
502check_failedWhatsApp did not answer (single-number requests); retry
503whatsapp_not_connectedThe WhatsApp account for this key isn't linked or is reconnecting. Log in and check the "Your WhatsApp" card on the dashboard.
